# Neutralis data purchase review

Updated 2026-09-07 by Astra, with three independent GPT research screens during the reported Claude quota limit. The founder requested a broader comparison and explicit API assessment before this important purchase. This review supersedes the initial three-provider preference as a procurement decision. Fifteen supplier/package routes were screened from public primary documentation; this is not an exhaustive market survey or a claim that their datasets passed acceptance. No vendor was contacted, account opened or subscription purchased. The monthly budget and contracting arrangement remain unset.

## Recommendation at this stage

Compare **Sharadar, Tiingo and FactSet PIT** as the next technical-clarification candidates. Keep **FMP** as an additional practical challenger and **CRSP plus S&P PIT** as a quality/price benchmark; LSEG is another credible institutional route. Obtain comparable package answers before selecting the two or three most promising evaluation samples. No supplier is an automatic winner. A missing public specification is an unanswered question; an explicitly incompatible field or history length is a constraint on the current design.

Prefer a usable historical archive plus automated updates. An API is valuable, but bulk delivery and API delivery are compatible: APIs often produce downloadable files. We should buy the underlying data and rights we need, then choose the delivery arrangement. A broker connection, chart subscription or generic API subscription does not establish those entitlements.

## What the first purchase should support

The initial [experiment](FIRST-EXPERIMENT.md) is a **proposed daily-data, monthly-rebalanced US equity momentum/profitability study**, not a frozen product requirement or a discovered edge. Its long window is development 2000–2012, validation 2013–2019 and final historical test 2020–2025, with preceding initialization history. Coverage may require a documented design change before examining returns; a shorter dataset cannot silently inherit those windows.

| Need | Buying requirement |
| --- | --- |
| Historical investment universe | Active and subsequently delisted common stocks; dated security and issuer identities, share classes, eligibility/classification evidence and then-known capitalization. Selecting the largest 500 each month requires the historical eligible population, not today's 500 largest stocks. Historical S&P 500 membership is not mandatory for this custom universe. |
| Prices and volume | Daily raw or auditable reconstructed open/close/volume, with defined sessions and validated total-return inputs. Daily prices support a declared execution approximation, not proof of achievable auction fills. |
| Annual fundamentals | Gross profit, or compatible revenue/costs, and assets from the original information vintage; fiscal period, units, public availability and revision semantics. Latest-restated values attached to old fiscal dates are inadequate. |
| Corporate actions and exits | Splits, dividend amounts and dates, share conversions, spinoffs, merger consideration and delisting outcomes. Unknown outcomes must remain visible; disappearance is neither an assumed total loss nor a magically available final-price exit. |
| Automation and reproducibility | A feasible initial download, scheduled updates/corrections, stable identifiers, known limits and licensed frozen input copies for reproducible research. |
| Actual use and total price | Two named users, private shared storage, Linux processing, backups, agreed retention and the exact required tables. Clarify external-model processing only for the workflow actually used. Numeric analysis need not submit raw licensed records to an external model. |

Original public-information reconstruction with an explicit delivery-delay assumption is acceptable under the proposed contract. A complete archive of every historical vendor delivery is not mandatory. Conversely, today's download hash cannot prove what the vendor delivered years ago.

Prediction-market arbitrage has a separate specification: timestamped executable bids/asks and depth, fees, venue/route identity, equivalent settlement terms and outcomes. Buying a stock-data subscription will not supply that evidence. News, macro vintages, options and intraday order books should be added for defined later hypotheses. SEC original filings can cross-check financial values; ALFRED can support a future macro-vintage study. [SEC data access](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [ALFRED](https://alfred.stlouisfed.org/help/downloaddata)

## API and bulk purchase criteria

| Capability | Practical value and acceptance evidence |
| --- | --- |
| Initial bulk history | Load the licensed universe once into immutable source files and normalized Parquet; query locally with DuckDB. Confirm exact years/tables, row counts, file dates, decompressed size and complete export entitlement. |
| Incremental API or daily files | Refresh new prices, filings and action changes automatically. An EOD/monthly study does not need a streaming subscription merely to automate updates. |
| Historical queries | Fetch specific periods, vanished symbols and original vintages. Test what `date`, `asof`, `asReported` and `adjusted` actually mean; similar parameter names serve different purposes. |
| Revision handling | Detect old rows that changed or were removed, preserve prior raw copies and identify correction timing. Updates must create a new research version, not silently change old experiment inputs. |
| Operational limits | Test pagination, rate/volume limits, stable filters, schema changes, retries, partial responses, export expiry and recovery. A single successful ticker request does not validate a full-universe download. |
| Forward availability | Verify usable data arrives before the strategy cutoff. Match history and update-feed definitions, sessions and actions. Raw timestamps and timezone interpretation must be explicit. |

For example, Massive's finalized bulk files are documented around 11 AM ET the following day. That is after the proposed next-open execution, so historical bulk availability alone does not establish a valid forward feed. A suitable earlier API route would need verification. Its aggregate split adjustment also does not mean dividend-inclusive total return. [Bulk conventions](https://massive.com/docs/flat-files/stocks/overview), [aggregate definitions](https://massive.com/docs/rest/stocks/aggregates/custom-bars)

Proposed architecture: a server-side scheduled downloader uses the licensed API/bulk service, records raw snapshots and revisions in private object storage, and prepares local research tables. Backtests read frozen inputs; Supabase holds manifests, jobs and concise results for the private dashboard. Keep vendor credentials server-side. This is an architecture recommendation, not an implemented or provisioned pipeline.

## Sharadar package and sample findings

The direct Fundamentals plan includes annual records, daily cap and actions but **not stock-price history**. Required direct tables would include `fundamentals` (ARY), `stocks`, `daily`, `tickers`, `actions` and `descriptions`. A corresponding full-history combined package is needed; investors/holdings data is not necessary for this hypothesis. The $29 Bundle is only five years; the public personal full-history Bundle is $69/month or $499/year. These are not two-user quotes. [Plan table](https://sharadar.com/subscribe)

The FAQ explicitly documents historical SIC changes and acquisition cash/share consideration, estimating about 90% acquisition coverage and excluding contingent value rights. It explicitly does **not** provide historical primary-listing exchange changes. Its description of `permaticker` as a security ID conflicts with the ticker page's issuer wording; share-class examples must resolve that. These findings improve some earlier unknowns while exposing a real eligibility gap. [FAQ](https://sharadar.com/docs/faqs), [identifiers](https://sharadar.com/docs/tickers)

`daily` documents historical as-reported market cap from December 1998, in USD millions, for the fundamentals-covered universe. `metrics` is a latest snapshot per ticker, not a substitute for historical momentum/volume calculation. [Daily](https://sharadar.com/docs/daily), [metrics](https://sharadar.com/docs/metrics)

One [public AAPL demonstration check](SHARADAR-PUBLIC-DEMO-CHECK.md) matched four FY2023 annual values and the filing/period dates to previously independently verified original SEC facts. Three ordinary price sessions and three cap rows also returned successfully. This does not accept the broader population, historical feed versions, action ledger or license. The requested `fiscalperiod` was absent from that projection; the vendor schema/sample question remains open.

## Price comparison and purchase sequence

The relevant cost is the **complete licensed arrangement**, not the cheapest displayed API plan: required tables, initial history/bulk fees, two users, update/correction access, possible exchange/non-display fees, storage/retention and integration effort. Public individual prices are useful reference points only. They do not establish that two individual accounts can feed a shared database.

Illustrative package traps checked today: Tiingo's fundamentals requires an add-on quote beyond its base plan; FMP bulk/batch belongs to a higher tier; EODHD All-in-One does not include its Extended Fundamentals bulk offering. [Tiingo](https://www.tiingo.com/documentation/fundamentals), [FMP plans](https://site.financialmodelingprep.com/developer/docs/pricing), [EODHD bulk](https://eodhd.com/financial-apis/bulk-fundamentals-api-via-extended-fundamentals-plan)

Sharadar personal terms exclude pooled access and require deletion of underlying copies after termination; Tiingo and SimFin also have retention constraints. An archive's technical portability does not grant permanent usage rights. A suitable written arrangement can be considered; unrestricted external-model uploads are not assumed necessary. [Sharadar terms](https://sharadar.com/terms), [Tiingo terms](https://api.tiingo.com/tos/), [SimFin cancellation terms](https://www.simfin.com/en/prices/)

1. **Public screen: completed, with explicit unknowns.** Use this matrix to compare concrete packages and scope choices, not to declare a universal best data website.
2. **Comparable written answers: drafted, unsent.** The [vendor-neutral inquiry](DATA-INQUIRY-DRAFT.md) asks for required tables/history, API/bulk/update details, evaluation terms and the actual two-user quote. Contracting subscriber/account arrangement and budget remain founder decisions. Sending has not been authorized.
3. **Same adverse-case sample for finalists: pending.** Audit historical cross-sections, restatements, disappeared companies, actions and source revisions. Measure gaps, then decide whether a bounded pilot is justified. See [acceptance gates](DATA-SHORTLIST.md).
4. **Purchase decision: pending evidence.** Compare qualified total prices and integration effort, document remaining limitations and choose the smallest suitable commitment. An annual discount should not precede a credible sample and understood retention rights.
