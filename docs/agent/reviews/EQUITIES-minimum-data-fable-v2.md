## Finding 1 — v4's price-observation source clock is not established by the documented bar fields
v4 §3 admits a record only with `source_record_time ≤ deadline` **and** `retrieved_at ≤ deadline`, and §8 routes warm-up, development and validation through the same admission. The note establishes that Alpaca bar timestamps mark interval starts and that the documented bar fields carry no publication or revision clock; auction records and action events do carry clocks. This is narrower than proving that no feed or record can supply one; it means the reviewed documentation has not shown it.
- A later capture-only convention would need its own named semantics, for example `retrieval_clock_admission`: admission by `retrieved_at` alone for bars, with the explicit loss that independent source-publication evidence is absent and corrections are detectable only by re-retrieval. It must never be written into `source_record_time`, which the source note forbids. Whether such a convention is acceptable is a registration decision for the co-heads, not adopted here.
- Historical windows have no contemporaneous retrieval; they remain a distinct, unapproved `historical_reconstruction` class. Consequence if ever approved: P1's development-window `w` would derive from reconstructed data and must be labelled so in every report.

## Finding 2 — positive action coverage across all required types is not established, and an issuer schedule does not close it
v4 §5 requires an admitted coverage statement through the fill session before any fill; the note correctly records that Alpaca disclaims creation timing, an empty response is not proof, and replay proves only published mutations. An issuer's quarterly distribution schedule compared with vendor records is a **possible reference approach with a coverage-scope gap**: it can only speak to scheduled distributions, not splits, special distributions, terminations or other action types v4 requires covered. It therefore stays unadmitted for every instrument until positive evidence covers the required type and date universe. v1's "feasible for SPY, infeasible for 30–50 stocks" is withdrawn; neither is established.

## Finding 3 — official-open mapping and access are both open
v4 §3 requires the primary regular-session official opening price with the source's definition quoted. The note's auction schema (price, timestamp, exchange, condition in opening arrays) is a candidate; which record is the primary-listing 09:30 core opening auction rather than an early auction or another venue's print is unproven. Documentation may partly resolve this through condition and venue code tables; a delivered sample is needed to confirm. The note records that calendar and auction routes are authenticated and that Basic is advertised at no charge with stated request limits; actual entitlement for a Neutralis identity, coverage of every route, two-founder shared use and model processing are unverified, and complete operating cost is unknown. v1's "zero cost beyond time" and implied free-tier entitlement are withdrawn.
