# Official-open documentary proof — ETF v4

Independent internal GPT documentary research, observed 2026-09-07 21:30–21:34 UTC. Read the complete minimum-data note and Fable's corrected feasibility challenge. Only public documentation and documentation-repository revision metadata were retrieved. No market-data endpoint, account, delivered sample, package, model, contact or strategy run; no source admission or registration amendment.

**Finding:** the condition/venue mapping is now documented sufficiently to identify a candidate SPY official-open announcement: an element of the opening array with `c = Q` and `x = P`. This is a synthesis of the explicit schema references, code definitions and issuer listing below, not proof of a complete, unique, timely delivered record. The remaining acceptance gaps are unverified, not demonstrated impossible.

| Requirement or claim | Status | Documentary evidence and limit |
| --- | --- | --- |
| Opening response structure | **Documented** | `stock_daily_auctions.o` contains `stock_auction` records; each requires `t,x,p,c`. The schema describes `p` as auction price. [Pinned Alpaca OpenAPI](https://raw.githubusercontent.com/alpacahq/cli/53606273aa230a40c64b783425dcb3f4423ede30/api/specs/market-data-api.json), those two schema objects. |
| Applying condition codes to auction `c` | **Documented, explicitly linked** | `stock_auction.properties.c` directs readers to `v2/stocks/meta/conditions/trade`; `x` separately directs readers to `v2/stocks/meta/exchanges`. This provides the required bridge; it is not an assumption that unrelated trade fields apply. [Same pinned schema](https://raw.githubusercontent.com/alpacahq/cli/53606273aa230a40c64b783425dcb3f4423ede30/api/specs/market-data-api.json). |
| `c=Q` versus `c=O` | **Documented distinction** | Q denotes **Market Center Official Open**; O denotes **Market Center Opening Trade**. CTS defines the former as “Indicates the ‘Official’ opening value as determined by a Market Center.” The latter concerns a single-priced opening transaction under Rule 611(b)(3). They are distinct classifications even if their prices happen to agree. [CTS v2.11b](https://www.ctaplan.com/publicdocs/ctaplan/CTS_Pillar_Output_Specification.pdf), printed pp. 82, 101–102. |
| Substituting the aggregate daily open | **Contradicted as a guaranteed equivalent** | Alpaca excludes Q from aggregate open/close, high/low and volume updates; O is eligible for those updates. Its open is the first eligible trade under aggregation rules, not a declaration of the primary venue's official opening value. Numeric coincidence would not establish equivalence. [Alpaca FAQ](https://docs.alpaca.markets/us/docs/market-data-faq), aggregation table and update rules. |
| Venue code and SPY primary listing | **Documented** | Alpaca's exchange documentation maps P to NYSE Arca and Q to NASDAQ OMX. Thus `x=Q` is a venue code, not the official-open condition. CTS also maps participant P to Arca. The issuer lists SPY, CUSIP 78462F103 / ISIN US78462F1030, on NYSE Arca as of September 7, 2026. [Alpaca Exchange enum](https://alpaca.markets/sdks/python/api_reference/data/enums.html#alpaca.data.enums.Exchange), [CTS printed pp. 79, 81](https://www.ctaplan.com/publicdocs/ctaplan/CTS_Pillar_Output_Specification.pdf), [issuer listing](https://www.ssga.com/us/en/intermediary/etfs/state-street-spdr-sp-500-etf-trust-spy). This current listing is not an effective-dated historical listing receipt. |
| Early versus core opening | **Schedule documented; complete selection contract unverified** | Arca lists a 04:00 ET early auction and 09:30 ET core auction. An opening-array member cannot qualify solely because it is first. [NYSE hours](https://www.nyse.com/trade/hours-calendars). A historical June 1, 2015 NYSE notice also describes a separate Q official-open report for the first core-session trade when Arca opens on a quote; this supports the distinction but is not a complete current implementation specification. [NYSE notice, p. 2](https://www.nyse.com/publicdocs/nyse/markets/nyse/Pillar_Trader_Update_June_2015.pdf). |

The quoted CTS definition plus the explicit Alpaca cross-reference closes the earlier missing semantic bridge. A primary-venue official announcement is consequently a concrete documentary candidate, without replacing it by an O trade or daily bar. Still unresolved: current guarantees distinguishing early/core/delayed openings; selection and supersession when several primary official announcements exist; corrections/cancellations and missing records; documented source-publication/revision semantics for `t` and capture by v4's noon deadline; actual endpoint entitlement and coverage. The auction timestamp schema specifies RFC 3339 precision, not a publication/revision clock. Only the **closing** array documents triplet deduplication with earliest timestamp; do not extend that rule to opening records. [Pinned schema](https://raw.githubusercontent.com/alpacahq/cli/53606273aa230a40c64b783425dcb3f4423ede30/api/specs/market-data-api.json).

No returned observation has been admitted. Action coverage, historical availability and rights remain separate prerequisites. Full v4 acceptance is still unmet on the evidence examined; this is a narrower, actionable evidence gap, not a finding that Alpaca cannot supply an official open.
