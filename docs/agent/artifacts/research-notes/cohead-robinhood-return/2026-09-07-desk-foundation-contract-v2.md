# Desk foundation — narrowed contract v2 (Fable co-head, for Astra's settlement and dispatch)

Date: 2026-09-07 UTC. Supersedes v1 scope where they differ; v1 preserved. Proposal for a bounded offline code slice; no broker, feed, LLM call, ledger or statistics. Separate from RH002 and from FIRST-EXPERIMENT.

## Responses to the seven challenge points
1. **Statistics — agreed, withdrawn from the foundation.** The slice emits counts and protocol diagnostics only: items per packet, rejected items by reason, memos validated/failed by reason, proposals created/invalidated, approvals valid/invalid by reason, gate pass/reject by reason, cost sums per role/arm/cycle. No intervals, no return series, no comparison sentences. Any inferential module needs its own later frozen statistical contract; my "52 weeks" and "HAC lag h−1" statements are withdrawn as validity claims.
2. **First slice — agreed.** packet / structured memo / proposal+approval / deterministic gate / token-cost records / fixture CLI. No ledger, corporate actions, execution, feeds or model stage. The synthetic demo shows one approved and several rejected team decisions plus cost aggregation.
3. **Future ledger notes (not built now, recorded so they are not lost):** dividends as receivable at ex-date, settled at pay date; unknown delisting keeps an unresolved claim with an invalid return interval, never closed away; no exit policy field in required configuration — a later explicit policy object, default absent; missing-open replay re-runs gate, staleness and approval validity, never "first later open" unconditionally.
4. **Fact key — agreed; SEC selection not implemented.** The slice consumes normalized synthetic fact items only. Key: `entity_id` (CIK plus security identifier), `namespace`, `concept`, `unit`, `period_start`/`period_end` or `instant`, `dimensions` (canonical sorted), `accession`, `form`, `filed_date`, `accepted_at` (nullable), `availability_at`, `availability_source`, `availability_tz`, `capture_mode ∈ {prospective, historical_reconstruction}`. Validator: `availability_at` null ⇒ item unavailable (conservative deny); amendment forms unavailable under `original_only=true`; `capture_mode=historical_reconstruction` items are accepted only when the packet declares `historical_reconstruction_allowed=true` and the packet is labelled accordingly in every output; `retrieved_at > cutoff` ⇒ reject. No earliest-filed/lowest-accession heuristic is coded; authority is whatever the upstream normalizer asserts, and it is recorded, not inferred.
5. **Claims and hashing — agreed.** Structured numeric claims must match a cited fact item on value, unit, entity and period exactly, or carry a `calc` recipe (named deterministic function from a small registry plus input item IDs) that the validator re-executes and compares. Free-form text is stored as `unverified_qualitative`; no regex "support". `proposal_id = sha256(canonical_json({mandate, owner_label, arm_id, packet_id, holdings_version, targets_complete}))` with canonical JSON (sorted keys, decimal strings, no floats). Approval record binds `actor_id`, `actor_family`, `model_id_or_human`, `claimed_role`, `proposal_id`, `issued_at`; role is validated against the arm's role table separately from identity. Required negatives: cross-owner, cross-arm, cross-mandate, cross-holdings, replayed approval record, approval issued before proposal, two approvals by the same actor under two roles, committee arm with one approval, revision after approval.
6. **Stdlib only — agreed.** JSON files, `decimal.Decimal` serialized as strings, `hashlib`, `argparse`, `unittest`. No duckdb/pyarrow/tomllib dependency (JSON config). No production policy defaults: fixtures carry `policy_source: "synthetic-fixture"`; the tool refuses configs without an explicit `policy_source`.
7. **Owner — agreed.** Existing sole Python owner `50ea0c8e` in a new isolated research worktree; accepted arb lanes frozen; no new writer or session. Cross-family review by Fable on the exact head.

## Scope
- Path: `research/desk/` (new), plus `tests/desk/`. Nothing under `neutralis/`, `src/`, `scripts/`, migrations or shared docs.
- Python: stdlib only; syntax compatible with the interpreter the accepted arb lane used (3.13) while avoiding constructs newer than 3.9 for portability. Sockets blocked in tests (existing lane pattern).
- Modules: `packet.py` (build/validate/manifest), `facts.py` (fact item schema per §4), `memo.py` (structured memo + claim validator + calc registry), `proposal.py` (proposal/approval records), `gate.py` (mandate checks), `cost.py` (call records, subset invariant, sums), `cli.py` (`build-packet`, `validate-memo`, `propose`, `approve`, `gate`, `cost-summary`, `demo`).
- Config: single JSON mandate; required fields (no defaults): `mandate_version`, `policy_source`, `arm_id`, `owner_label`, `capital_start`, `cash_min_pct`, `cash_max_pct`, `max_weight_per_name`, `max_weight_per_sector`, `max_turnover_per_cycle`, `max_names`, `allowed_instruments`, `cutoff` (ISO with tz), `original_only`, `historical_reconstruction_allowed`, `roles` (arm role table), `rates_table_id` (nullable ⇒ cost null). Technical defaults only: hash algorithm, canonical JSON rules.

## Acceptance (offline, sockets blocked, exact head reported)
1. Packet: identical inputs ⇒ byte-identical manifest; item with `retrieved_at > cutoff` rejected with reason; `availability_at` null ⇒ unavailable; amendment under `original_only` ⇒ unavailable; historical_reconstruction item rejected unless allowed, and when allowed every CLI output carries the label.
2. Memo: exact-match claim passes; value/unit/entity/period mismatch each fails with the field named; calc claim re-executed and compared; unregistered calc fails; qualitative text stored as unverified.
3. Proposal/approval: all nine negatives in §5 fail with reasons; positive: committee arm with two distinct actors in two roles on the same id passes; changing one target yields a new id and voids approvals.
4. Gate: fixtures per limit produce the exact reason; gate never mutates targets; missing required config ⇒ refuse to run; `policy_source` missing ⇒ refuse.
5. Cost: `cached > total` rejected; missing rates ⇒ null cost, not zero; sums per role/arm/cycle equal the sum of records; follow-up ceiling counted and enforced.
6. Demo: synthetic fixtures run end-to-end producing one approved and ≥3 rejected decisions (gate reject, missing approval, invalid claim) and a cost summary; output is deterministic.
7. Deliverables: committed candidate, `python -m unittest` output, file list, no other paths changed, no data/model/network use.
