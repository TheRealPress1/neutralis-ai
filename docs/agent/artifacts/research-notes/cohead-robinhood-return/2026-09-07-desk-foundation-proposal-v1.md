## 1. The four conventions, resolved

### 1.1 Token accounting (cache subset)
Record per call: `input_total`, `input_cached` (≤ `input_total`), `output`, `model_id`, `role`, `arm`, `cycle_id`. Derived: `input_uncached = input_total − input_cached`. Cost = `input_uncached·p_in + input_cached·p_cached + output·p_out` with rates stored as dated config, never hard-coded. Invariants enforced by the validator: cached ≤ total; a call with no rate table yields `cost = null`, not zero; cycle totals are sums of call records, never estimates. Follow-up ceiling is a counted field, not prose.

### 1.2 Dependence-aware statistical claims
Three classes of statement, each with a gate the report generator enforces:
- **Descriptive diagnostics** (allowed from week 1): audited factual error rate per memo; hard-control rejections; Brier score per forecast set. Standard errors clustered two-way by decision week and sector; reported as intervals, labelled descriptive.
- **Return comparisons** (allowed only after a preregistered minimum): arm-vs-benchmark and A2-vs-A1 weekly net return differences with HAC (Newey–West) standard errors, lag = forecast/holding horizon − 1 in weeks, plus a stationary block bootstrap with block length ≥ horizon. Minimum before any interval is printed: 52 weekly observations. Below that, the report prints cumulative return and drawdown only, with the sentence "insufficient sample for a comparison statement".
- **Edge or outperformance language**: never generated by the tool. It is a human conclusion requiring an independent reproduction and a preregistered criterion; the tool emits numbers and the sample-size status only.
Twelve or twenty-six weeks therefore produce diagnostics and a decision about continuing the process, not a performance verdict.

### 1.3 Halts, unavailable prices, delistings, corporate actions (paper ledger)
- **Execution convention**: orders generated at cutoff (Friday 16:00 ET) execute at the next regular session open; fill = open × (1 ± cost_bps/10⁴) ± half quoted spread if a spread observation exists, else open × (1 ± cost_bps/10⁴) with `spread_source = "none"`.
- **Missing open on the execution day**: the order carries forward up to `max_fill_delay_sessions` (config); first available open fills; beyond that the order expires as `unfilled` with reason. No synthetic price is ever invented.
- **Trading halt during the holding period**: position marked at last available close with `valuation = "stale"` and days-stale count; no P&L is realised; exits are queued and follow the missing-open rule when trading resumes.
- **Delisting**: if the actions source provides consideration (cash, shares of acquirer at a ratio) the ledger applies it on the effective date; if not, the position is closed at `terminal_value = null` and the arm's return series carries a documented gap plus a sensitivity line at 0 and at last close. The report shows both; neither is "the" result.
- **Splits**: quantity × ratio on ex-date, unadjusted prices throughout; **cash dividends**: cash credited on pay date (ex-date recorded), so cash timing is honest; the benchmark uses the identical convention (dividends as cash, reinvested only at the next rebalance).
- **Ambiguity rule**: any ledger action that would require an assumption not present in the actions source is refused and logged; the ledger stops for that name until a human supplies a dated record.

### 1.4 Original accession and vintage (fundamentals)
Source of record: SEC EDGAR companyfacts and, where the quarterly Financial Statement Data Sets cover the period, the SUB table's `accepted` timestamp.
- Fact selection for (concept, unit, period_end, fy, fp) at cutoff C: candidates = facts whose `form ∈ {10-K, 10-Q}` (amendments 10-K/A, 10-Q/A excluded unless no original exists) and `filed ≤ C_date`. Choose the **earliest `filed`**; tie-break lowest accession number. Record `accn`, `filed`, `form`.
- Availability time: if the SUB `accepted` timestamp is available and ≤ C, the fact is usable at C; if only `filed` (date) is known, the fact becomes usable at the first regular session **after** `filed` (conservative, independent of EDGAR's after-hours rule).
- Later refilings of the same period (e.g., prior-year comparatives in a new 10-K) are never substituted; restatement detection = a different `val` for the same key with a later `filed`, recorded as an event, not applied to earlier decisions.
- Missing `assets` or `gross profit` at C → the metric is "unavailable at C"; the packet records the gap and the analyst memo may not assert a number.

## 2. Paper mandate (proposed structure; numeric values are required configuration)
`mandate.toml` fields, all explicit, no defaults for policy values (the tool refuses to run with any unset):
- identity: `mandate_version`, `arm_id`, `owner_label` (founder label only; no account IDs in research records).
- capital: `capital_start` per arm; `cash_min_pct`, `cash_max_pct`.
- universe: `selection_rule_id`, `n_names`, `lookback_sessions`, `index_list_source` (URL + retrieval time), `freeze_date`.
- limits: `max_weight_per_name`, `max_weight_per_sector`, `max_turnover_per_cycle`, `max_names`, `allowed_instruments = ["US common stock"]`.
- cadence: `cutoff_weekday`, `cutoff_time_local`, `timezone = "America/New_York"`, `calendar = "XNYS"`.
- execution: `fill_convention`, `cost_bps`, `max_fill_delay_sessions`.
- objective exit rule (paper only): `stop_loss_pct`, `metric_floor_rules[]` (metric, floor, source), `halt_sessions_to_exit`; unknown-data behaviour is fixed by the tool as "no exit, flag".
- forecasts: `horizon_weeks`, question set IDs.
- models (stub in this milestone): `model_id`, `prompt_hash`, `rates_table_id` per role and arm.
- statistics: `min_weeks_for_comparison` (proposed 52), `bootstrap_block_weeks`.
Defaults are permitted only for technical constants (hash algorithm, file formats, timezone name).

## 3. Smallest buildable module — scope and acceptance contract

Location: `research/desk/` (new, outside `neutralis/`), Python 3.11+, dependencies limited to what the repo already uses plus `duckdb`/`pyarrow` if not present (propose exact versions in the candidate). No network at runtime; a socket-blocking test fixture like the ARB lanes.

Modules (one owner, sequential commits, each with tests):
1. `packet/` — builds `EvidencePacket` from local sources (prices Parquet, actions CSV, companyfacts JSON snapshots, macro CSV): computes per-item `content_sha256`, `source_url`, `retrieved_at`, `available_at`; rejects any item with `retrieved_at > cutoff` or `available_at > cutoff`; writes `packet_manifest.json` deterministically (byte-identical on rerun).
2. `memo/` — schema + validator for analyst assessments: every numeric claim carries a `packet_item_id`; uncited numbers fail validation; `unknown` is a first-class value. Fixture memos are hand-written; no model stage.
3. `proposal/` — `Proposal` record with `proposal_id = sha256(mandate_version ‖ packet_id ‖ holdings_version ‖ canonical targets)`; `Approval` binds `proposal_id` + `approver_role` + `arm_id` + timestamp; any target or input change yields a new id and voids approvals; committee arm requires two distinct approver roles on one id.
4. `gate/` — deterministic risk gate: validates a proposal against the mandate; returns `pass` or `reject[reasons]`; never modifies weights.
5. `ledger/` — per-arm paper ledger implementing §1.3; deterministic replay from records; cost records per §1.1.
6. `report/` — diagnostics and return summaries implementing §1.2 with the statement guard.
7. `cli` — `desk packet build`, `desk validate`, `desk run --arm A1|A2|P0 --fixtures` (fixtures only in this milestone).

Acceptance (all offline, sockets blocked, exact head reported):
- Packet: same inputs → identical manifest bytes; a post-cutoff item is rejected with a named reason; coverage gaps are listed, not silently dropped.
- Memo: fixture with an uncited number fails; fixture with `unknown` passes.
- Proposal/approval: modifying one target after approval invalidates it; committee arm with one approval does not pass; two approvals on different ids do not pass.
- Gate: fixtures for each limit produce exact rejection reasons; no weight is altered.
- Ledger known-answer fixtures: split, cash dividend (ex vs pay), missing open within and beyond delay, halt with stale valuation, delisting with and without consideration (the latter produces the two sensitivity lines), turnover cap. Replay reproduces balances byte-for-byte.
- Cost: cached > total rejected; missing rate table → null cost, not zero; cycle totals equal sum of calls.
- Report: below `min_weeks_for_comparison` no interval or comparison sentence is emitted; above it, HAC and bootstrap intervals are produced on synthetic series with a known answer.
- Synthetic controls: a generated universe with known drift/vol; arm P0 ledger return matches the analytically computed path within rounding; a deliberately leaked packet is rejected.
- Deliverables: committed candidate, test output, file list, no product/Python-engine files touched, no data purchased, no model called.

Out of scope for this milestone: any LLM call, any real price feed, Robinhood, the historical factor experiment, live exits, dashboards.
