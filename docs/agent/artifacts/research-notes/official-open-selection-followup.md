# Official-open selection: NYSE/CTA documentary follow-up

2026-09-07 UTC. Internal GPT research assistance; documentary findings only. Read the existing official-open note and minimum-data settlement. No data, account, market endpoint, service, package, or runtime was accessed; ETF v4 and admission status remain unchanged. Page references below are printed PDF pages.

1. **Current Arca documentation positively ties the official-open Q to the core session.** NYSE's *Functional Differences*, version 31.0 (2026-08-03; version history p33), row 57 p30, assigns Arca EQ the standard behavior: a core auction ending in a trade produces a separate Q with that trade's details; if it ends in a quote, Q follows the first Exchange trade in the core session. Row 1 pp1–2 distinguishes Arca's 04:00–09:30 early session from its 09:30–16:00 core session. This supplies a current core-event rule and a documented reason for Q after 09:30. **Limit:** it does not establish an exact-09:30 timestamp requirement, an exhaustive halted/delayed-opening selection rule, or a first/last-array-element rule. It does not prove that every historical early-session Q is absent. The closing-price republication schedule in adjacent row 56 is not a Q rule. [NYSE Functional Differences](https://www.nyse.com/publicdocs/nyse/markets/nyse/Functional_Differences_NYSE_Pillar.pdf)

2. **Corrections have explicit record identity; timestamp sorting alone is unsupported.** NYSE's *Pillar Trades Client Specification* 2.5h (2025-03-28), §§3–4 pp9–11, defines cancel 221 and correction 222 using `OriginalTradeID`; correction supplies a replacement `TradeID`, price and conditions, expressly including Q. It directs recipients to remove canceled records or correct the targeted record. [NYSE Trades specification](https://www.nyse.com/publicdocs/nyse/data/NYSE_Pillar_Trades_Client_Specification_v2.5h.pdf) CTA/CTS 2.11b §§6.7.2–3 pp53–56 and §§6.7.9–10 pp61–64 similarly target the original or latest correction's participant reference. Canceled/error records cannot be further corrected; a replacement requires a new trade. Both legacy and fractional message forms are documented. **Limit:** these source protocols do not establish how the vendor's auction array exposes, applies or omits this lineage. No earliest/latest-Q deduplication recipe follows. [CTS specification](https://www.ctaplan.com/publicdocs/ctaplan/CTS_Pillar_Output_Specification.pdf)

3. **Source clocks are defined, but the vendor timestamp mapping remains unverified.** CTS §4.4 p26 defines exchange-origin `Timestamp 1` as matching-engine publication time; CTS-generated messages instead carry current SIP time. §3.5.8 p20 defines SIP block time as completion of SIP processing; retransmissions retain original processing timing. [CTS specification](https://www.ctaplan.com/publicdocs/ctaplan/CTS_Pillar_Output_Specification.pdf) NYSE Trades §§2–4 pp7–11 defines `SourceTime`/`SourceTimeNS` as message generation in the order book, including each cancellation/correction message. [NYSE Trades specification](https://www.nyse.com/publicdocs/nyse/data/NYSE_Pillar_Trades_Client_Specification_v2.5h.pdf) **Limit:** none establishes which source clock becomes the vendor's auction `t`, recipient capture time, availability by the noon deadline, or finality against later corrections. Those remain unresolved, not impossible.
