Synthetic fixture sources explicitly say synthetic and internally authored. Packet includes cutoff, required coverage, all provided facts and named gaps. Required unknown/missing facts produce an incomplete packet and block decision admission; no silent exclusion or remembered/model replacement. 3. Analyst assessment. Structured factual claims carry packet/fact IDs and must match exact cited value, entity, unit and period, or the supported deterministic calculation. Unknown is valid information, not fabricated zero. Unsupported recipe, mismatched citation, changed packet or invented number rejects. Qualitative thesis/rationale is explicitly unverified analyst judgment; schema validation cannot certify prose truth. No account records, broker permissions or secrets.
4. Proposal. Owner identity, arm, full mandate hash, packet hash, holdings version/hash, validated memo hashes, complete canonical target weights and decision deadline form one content-addressed proposal. Changes to any input, including cash, deadlines or limits, make a new ID. Targets include every held security or explicit zero disposition; reject duplicate identifiers, NaN/infinite, negative, unsupported instrument, or conflicting sector/identity metadata. No short, leverage or execution quantities; weights refer only to supplied synthetic reference valuations. One-PM and two-PM arms have separate identities and holdings.
5. PM approval. A configured roster fixes distinct synthetic actor IDs and allowed roles per owner/arm. An approval binds actor, owner, arm, proposal ID and aware timestamp within proposal validity. A role string alone does not identify a second actor. Reject unknown actor, duplicate actor pretending to be two roles, wrong owner/arm/mandate/packet/holdings, stale timestamp, changed target, or two different proposal versions. The single-PM arm needs its one assigned actor; committee requires both distinct assigned PMs accepting the exact final complete proposal. Disagreement/missing/stale evidence is reject; there is no committee-to-single fallback. This checks offline protocol identity only, not human authentication or signatures.
6. Risk gate and receipt. Require a UTC-aware evaluation_instant argument; use it for every freshness, validity and staleness check. One public decision entrypoint always runs validation, approvals and deterministic limits; no accepted flag trusted from input. Required synthetic mandate values: allowed instruments/universe with sector map, actor roster, per-name cap, per-sector cap, min/max cash, maximum active names, one-way turnover cap, validity horizon/freshness limits, and bounded follow-up count. Emit all stable named rejection reasons, actual evaluated input hashes and complete decisions. Replayed identical inputs give identical receipt bytes; changed state cannot reuse the earlier decision. No executable order, permit, broker adapter or automatic exit.
7. Cost records. Supply per-call unique ID, role, shared/arm bucket, cycle, model/config/rate-table IDs, success/failure, input_total, input_cached as subset, output and follow-up ordinal. Count failed calls and reject negative/noninteger counts, cached>total, duplicate IDs and over-limit follow-ups. A dated nonnegative explicit rate table defines per-million input, cached and output USD charges. Missing required rates yields null total with named unpriced rows, never zero or a partial total advertised as complete. Known costs use decimal arithmetic and include no cached double counting.
