## Current source-protocol follow-up

2026-09-07, 22:48 UTC. Internal GPT helper supplied three bounded findings; Astra reread the primary documents. NYSE Functional Differences v31.0 (August 3, 2026), row 57 p. 30, specifies a separate Q announcement following a core-auction trade. When the auction ends on a quote, Q follows the first exchange trade in the core session. Arca uses that standard behavior. **Inference:** requiring exactly 09:30 would exclude a documented valid case. This does not settle every halted/delayed opening or justify first/last array selection. [NYSE Functional Differences](https://www.nyse.com/publicdocs/nyse/markets/nyse/Functional_Differences_NYSE_Pillar.pdf).

NYSE Trades v2.5h, sections 3–4 pp. 9–11, identifies a cancellation/correction through `OriginalTradeID`; correction supplies a replacement `TradeID` and explicitly permits condition Q. It defines each message's source-generation time. **Inference:** correction processing needs record lineage; sorting timestamps is insufficient. Whether Alpaca's auction array preserves or applies this lineage remains unverified. [NYSE Trades specification](https://www.nyse.com/publicdocs/nyse/data/NYSE_Pillar_Trades_Client_Specification_v2.5h.pdf).

CTS v2.11b section 4.4 p. 26 distinguishes exchange matching-engine publication time from SIP-generated message time; section 3.5.8 p. 20 separately defines SIP processing time and retained timing for retransmissions. None establishes how Alpaca maps auction `t`, when a recipient obtained it, or finality by noon. [CTS specification](https://www.ctaplan.com/publicdocs/ctaplan/CTS_Pillar_Output_Specification.pdf).
