# Session handoff

Preserve enough external context for a new agent to act accurately without inheriting a transcript or another model's private memory.

## Save

Read the current project state and inspect live repository/PR facts within authorized scope. Record:

- Date, author/role, founder, repository, lane and exact working head.
- Outcome delivered, durable evidence and tests actually run.
- Open order, unfinished findings, dependencies and next owner/action.
- Allowed files, forbidden destinations, permissions and stopping point.
- Decisions with approval source and what they supersede.
- Environment requirements by name, never secret values.

Label memory entries as user, feedback, project or reference; distinguish observed, approved, proposed and superseded information. Index useful notes. Update rather than duplicating stale current-state claims. Do not convert one project exception into a universal skill rule.

Publish approved handoff files to the project's durable store before retiring the workspace. Temporary paths and uncommitted notes are not sufficient. Do not export raw customer communications, credentials or another founder's memory.

## Resume

Read the entrypoint, project profile, current state and relevant indexed notes. Reconcile them against the actual branch, PRs and environment. Verify current founder/workspace ownership and session IDs instead of trusting an old list.

Report discrepancies. Do not restart completed work, assume an ordered feature merged, or treat an old screenshot as the live deployment. Check installed skills and available tools separately from the saved workflow.

For a replacement writer, ensure the old session has stopped writing before beginning. If the destination is a new project, transfer reusable methods and approved preferences only; choose its own domain, design reference and authorization boundaries.
